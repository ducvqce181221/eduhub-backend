# 04 — Database Design
**Pre-Coding Documentation**  
*Project:* EduHub | *Version:* 1.5 | *Status:* Refined before coding

---

## 1. Database Strategy
PostgreSQL is the sole primary database in the project. Prisma ORM v7 with `@prisma/adapter-pg` driver adapter is used for declarative schema modeling (`schema.prisma`), configuration via `prisma.config.ts`, automated SQL migrations (`pnpm run db:migrate`), type-safe client generation into `src/generated/prisma`, relations, and transactional integrity.

## 2. Entity / Model Overview (16 Models, 5 Enums)

| Model | Purpose |
| :--- | :--- |
| **User** | Authentication identity, credentials hash, profile, role (`STUDENT`, `TEACHER`, `ADMIN`), account status. |
| **Category** | Groups courses into domains. Includes `IsActive` flag and deletion safeguard. |
| **Course** | Top-level learning product owned by a Teacher (`Status`: `DRAFT`, `PUBLISHED`, `ARCHIVED`). |
| **Chapter** | Groups ordered lessons within a course. |
| **Lesson** | Ordered learning unit within a chapter; requires a video before course publication; supports 0..N resources and 0..1 quiz. |
| **Video** | Video metadata for a lesson (`VideoUrl`, `DurationSeconds`). |
| **Resource** | Optional downloadable/reference materials (0..N per lesson; `FileSize` in integer bytes). |
| **Quiz** | Optional assessment attached to a lesson (0..1 per lesson); specifies `PassScore` percentage. |
| **Question** | Single-choice question belonging to a quiz, with assigned `Points`. |
| **Answer** | Answer option belonging to a question (minimum 2 per question, exactly 1 marked `IsCorrect = true`). |
| **Enrollment** | Student-to-course enrollment record (`Status`: `ACTIVE`, `COMPLETED`, `CANCELLED`). |
| **LessonProgress** | Student progress for a lesson (`WatchedSeconds`, `IsCompleted`, `CompletedAt`). |
| **QuizAttempt** | Student submission result for a quiz (`Score` float percentage, `IsPassed`, `StartedAt`, `SubmittedAt`). |
| **QuizAttemptAnswer** | Records individual question and chosen answer per attempt. |
| **Notification** | User-specific asynchronous notifications (`IsRead`, `Type` enum, `Title`, `Message`). |
| **Banner** | Promotional banners displayed on the Home carousel (`Title`, `ImageUrl`, `LinkUrl`, `Order`, `IsActive`). |


## 3. Relationships & Cardinality

| Relationship | Cardinality | Rule & Enforcement |
| :--- | :---: | :--- |
| **User → Course** | 1:N | A Teacher can own many courses; each course has exactly one owner (`teacherId`). Uses `onDelete: Restrict`. |
| **Category → Course** | 1:N | A category contains many courses; each course belongs to one category (`categoryId`). Uses `onDelete: Restrict`. |
| **Course → Chapter** | 1:N | A course contains one or more ordered chapters (`onDelete: Cascade`). |
| **Chapter → Lesson** | 1:N | A chapter contains one or more ordered lessons (`onDelete: Cascade`). |
| **Lesson → Video** | 1:0..1 $\rightarrow$ 1:1 | Schema allows 1:0..1 in draft state (`lessonId` `@unique`). Business logic strictly enforces **1:1 before publication** (`onDelete: Cascade`). |
| **Lesson → Resource** | 1:0..N | A lesson may have zero or many resources (`onDelete: Cascade`). |
| **Lesson → Quiz** | 1:0..1 | A lesson may have zero or one quiz (`lessonId` `@unique`, `onDelete: Cascade`). |
| **Quiz → Question** | 1:N | A quiz contains one or more questions (`onDelete: Cascade`). |
| **Question → Answer** | 1:N | Each single-choice question has $\ge 2$ answers; exactly one answer has `isCorrect = true` (`onDelete: Cascade`). |
| **User → Enrollment** | 1:N | A student can enroll in many courses (`@@unique([studentId, courseId])`). Uses `onDelete: Restrict`. |
| **Course → Enrollment** | 1:N | A course can have many enrolled students (`onDelete: Cascade`). |
| **User → LessonProgress** | 1:N | A student has progress records for accessed lessons (`@@unique([studentId, lessonId])`). Uses `onDelete: Restrict`. |
| **Lesson → LessonProgress** | 1:N | A lesson tracks progress across many students (`onDelete: Cascade` ensures clean teardown upon lesson deletion). |
| **User → QuizAttempt** | 1:N | A student can make unlimited attempts on a quiz. Uses `onDelete: Restrict`. |
| **Quiz → QuizAttempt** | 1:N | A quiz tracks multiple attempt submissions (`onDelete: Cascade`). |
| **QuizAttempt → QuizAttemptAnswer** | 1:N | An attempt records answers for each question submitted (`onDelete: Cascade`). |
| **User → Notification** | 1:N | A user receives notifications generated by domain events (`onDelete: Cascade`). |

## 4. Prisma 7 Configuration & Schema Reference

### 4.1 Central Configuration (`prisma.config.ts`)
In Prisma 7, datasource URLs, migrations, and seed scripts are managed centrally via `prisma.config.ts`:

```typescript
import "dotenv/config";
import { defineConfig, env } from "prisma/config";

export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: {
    path: "prisma/migrations",
    seed: "tsx ./prisma/seed.ts",
  },
  datasource: {
    url: env("DATABASE_URL"),
  },
});
```

### 4.2 Driver Adapter & Client Instantiation (`src/lib/prisma.ts`)
Prisma 7 standard SQL workflow uses a driver adapter (`@prisma/adapter-pg`). The client is initialized with the adapter and injected into NestJS via `PrismaService`:

```typescript
import "dotenv/config";
import { PrismaClient } from "../generated/prisma/client";
import { PrismaPg } from "@prisma/adapter-pg";

const rawDatabaseUrl = process.env.DATABASE_URL;
const databaseUrl = (rawDatabaseUrl ?? "").trim();
if (!databaseUrl) {
  throw new Error("DATABASE_URL is required");
}

const adapter = new PrismaPg({
  connectionString: databaseUrl,
});

export const prismaClientOptions = { adapter };

export function createPrismaClient() {
  return new PrismaClient(prismaClientOptions);
}
```

## 5. Learning Progress Model & Watch Threshold
1. **Watch Threshold Rule:** A video is considered watched when:
   $$\text{WatchedSeconds} \ge 0.90 \times \text{Video.DurationSeconds} \quad (\ge 90\%)$$
2. **Quiz Completion Rule:** If a lesson has a quiz attached, the student must achieve $\ge 1$ attempt with $\text{IsPassed} = \text{true}$ where:
   $$\text{Score} = \left(\frac{\sum \text{Points of Correct Answers}}{\sum \text{Total Possible Points}}\right) \times 100 \ge \text{Quiz.PassScore}$$
3. **Automatic Lesson Completion:** A lesson is automatically marked `isCompleted = true` and `completedAt = now()` during `PUT /lessons/:id/progress` or `POST /quizzes/:id/attempts` when:
   - Video watch threshold ($\ge 90\%$) is satisfied, **AND**
   - Quiz requirement (passing attempt exists, if quiz attached) is satisfied.
4. **Dynamic Course Progress (Single Source of Truth):**
   $$\text{CourseProgress (\%)} = \text{TotalLessons} > 0 ? \left(\frac{\text{Count of Completed Lessons in Course}}{\text{Total Lessons in Course}}\right) \times 100 : 0$$
   - Progress is dynamically derived directly from `LessonProgress` records on-demand (for both student dashboards and teacher reports), eliminating stale status bugs.
   - When $\text{CourseProgress} = 100\%$, `Enrollment.Status` is set to `COMPLETED` and `Enrollment.CompletedAt = now()`.

## 6. Course Publish-Ready Checklist
Before a course transitions from `DRAFT` to `PUBLISHED` (`PATCH /courses/:id/publish`), backend business logic executes the following atomic verification:
1. **Course Metadata:** `title`, `description` (non-empty), `categoryId` (active category), `level`, and `thumbnailUrl` (non-empty) are present and valid.
2. **Chapters:** Course contains at least 1 Chapter ($\ge 1$).
3. **Lessons:** Every chapter contains at least 1 Lesson ($\ge 1$).
4. **Videos:** Every lesson contains a valid Video record (`videoUrl` present and `durationSeconds > 0`).
5. **Quizzes (if attached):** Any lesson quiz must contain at least 1 Question, and each question must have $\ge 2$ Answers with exactly 1 correct answer.

If any criterion fails, the API rejects the publish request with `422 Unprocessable Entity` accompanied by a detailed list of missing requirements.

## 7. Transaction Boundaries (`prisma.$transaction`)
- **Quiz Submission:** Atomically executes inside `prisma.$transaction(async (tx) => { ... })`: verifies enrolled state, evaluates submitted answers, records `QuizAttempt` and `QuizAttemptAnswer` rows, evaluates lesson completion, updates `LessonProgress` if pass condition is met, checks course 100% completion (updates `Enrollment` and publishes `course.completed` event if applicable), and dispatches `quiz.submitted` event.
- **Lesson Progress Update:** Atomically updates `watchedSeconds` (clamped), evaluates lesson completion, checks course completion (updates `Enrollment` to `COMPLETED` and dispatches `course.completed` if 100% reached).
- **Curriculum Floor Enforcement:** When deleting a chapter or lesson, validates that a `PUBLISHED` course will not be stripped below 1 chapter and 1 lesson per chapter (rejects with `400 Bad Request` if violated).
- **Curriculum Reordering:** Batch updates chapter or lesson `order` fields atomically inside `prisma.$transaction` to prevent unique constraint collisions on `@@unique([courseId, order])`.
- **Course Publishing:** Validates full course hierarchy and updates `status = 'PUBLISHED'` and `publishedAt = new Date()`.
- **Enrollment Creation:** Atomically checks seat/status, creates `Enrollment`, and queues `course.enrolled` event.
- **Category Deletion:** Verifies `prisma.course.count({ where: { categoryId } }) === 0` before executing delete.

## 8. Database Seeding Configuration
Database seeding initializes essential baseline data (initial Admin user, standard categories, sample course content for local development). In Prisma 7, seeding is configured directly inside `prisma.config.ts`:
```typescript
migrations: {
  path: "prisma/migrations",
  seed: "tsx ./prisma/seed.ts",
}
```
Executed via:
```bash
pnpm run db:seed
# or: pnpm prisma db seed
```
